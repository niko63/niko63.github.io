2. Comment lire un message d’erreur : exemple

expected input is missing "nomVariable" signifie que le contrat de la tâche attend une donnée (nomVariable) que le formulaire n’a pas transmise. Les opérations qui devaient mettre à jour la BDM à partir de cette entrée ne peuvent donc pas s’exécuter.

Il faut vérifier trois choses :

  1. le nom de l’entrée dans le contrat de la tâche ;
  2. la correspondance avec la donnée envoyée par le formulaire (UI Designer) ;
  3. l’opération qui utilise cette entrée.
Attention à l’orthographeUne différence d’orthographe ou de majuscule entre ces trois éléments suffit à provoquer l’erreur.

3. Règle de travail

  • Formulez une hypothèse : « l’entrée du contrat n’est pas alimentée ».
  • Vérifiez-la avec la vue ou le log adapté (tableau ci-dessus).
  • Corrigez une seule chose à la fois, puis relancez un nouveau cas. Un cas déjà en erreur garde l’ancien état.
  • Notez ce que vous avez trouvé avant d’appeler l’enseignant.
Appeler l’enseignantAppelez seulement après avoir consulté ces sources et noté ce que vous avez trouvé : message d’erreur, vue consultée, hypothèse testée.

5. Liste de contrôle avant d’appeler

  • J’ai regardé les vues Statut de validation et Problèmes.
  • J’ai lu le message d’erreur en entier.
  • J’ai consulté le log du moteur (ou le terminal du simulateur pour l’API).
  • J’ai vérifié la valeur de la variable concernée.
  • J’ai relu l’orthographe des noms (contrat, formulaire, opération).
  • J’ai relancé un nouveau cas après ma correction.
  • Je sais dire ce que j’ai essayé et ce que j’ai observé.
Réflexe à éviterModifier plusieurs éléments à la fois : on ne sait plus ce qui a corrigé, ou aggravé, le problème.
